PetPal Booking

petpal-booking.example · Vite + React + Supabase on Netlify · pet-sitting marketplace, live with real customers
Demo report. PetPal Booking is a fictional application invented for this example. The findings are written the way real ones read, but no real product was audited to produce this page.
CheckVerdictEvidence
1 · Forces HTTPSRedirect + HSTS PASS Netlify default. http:// → 301 → https. HSTS absent, which is worth adding, but the redirect is the part that matters and it works.
2 · Passwords hashedOr managed auth FAIL Supabase Auth is used for login, but src/pages/AdminSetup.jsx:64 also writes to a custom staff table with a password column, plain text, compared with === at src/lib/staffAuth.js:22. 14 rows currently in that table. Two auth systems, and the second one is the one that is wrong.
3 · Bot protectionEvery public POST FAIL Six unauthenticated POST endpoints, none protected. /api/booking-request probed with 40 consecutive requests: all 40 accepted, all 40 wrote a row and sent an email. Nothing rate limits, nothing challenges, nothing deduplicates.
4 · Sessions expireFinite TTL + rotation FAIL The Supabase session is bypassed for staff. src/lib/staffAuth.js:39 signs its own token with jwt.sign(payload, SECRET) and no expiresIn, then stores it in localStorage. Decoded a live token: no exp claim. These never expire and cannot be revoked.
5 · CSRF protectionTokens or SameSite PARTIAL Reads are Bearer-token from localStorage, which is not CSRF-reachable, so most of the surface is incidentally safe. But /api/cancel-booking accepts a plain form POST authenticated by a cookie set at src/lib/staffAuth.js:47 with no SameSite attribute. One route, real exposure.
6 · Reset links one-timeTTL ≤ 1h, consumed FAIL api/reset.js:31 builds the reset link as md5(email + JWT_SECRET). Deterministic: the same address always produces the same link, it never expires, and it is reusable forever. Anyone who learns the secret can mint a takeover link for any address.
7 · Scoped DB keyAnon in browser only FAIL The service-role key is in the production bundle. .env sets VITE_SUPABASE_SERVICE_KEY, and the VITE_ prefix means Vite inlines it at build time. Found in the deployed asset assets/index-8f21ac.js (redacted here, value verified). Row-level security is also off on 7 of 9 tables, so this key reads and writes everything, including the plaintext password column from check 2. Rotate immediately — this key has been served to every visitor since deploy.
8 · Clean logsNo credentials logged FAIL api/login.js:12 is console.log("login attempt", req.body), which prints the submitted password into Netlify function logs on every attempt. Two more instances of the same shape at api/reset.js:18 and api/staff-invite.js:26.
9 · Billing alertsCap on every backend FAIL No cap anywhere. The Resend key sends on an unauthenticated route (check 3), and the OpenAI key backs a public "describe your pet" field with no auth and no limit — a scraper finding that endpoint runs the bill up unattended.
10 · Automated backupsRan, retained, restorable FAIL Supabase free tier: no platform backups, confirmed on the billing page rather than assumed. No backup job in the repo, no dump on disk, no scheduled task. The database is also the only copy of every booking, and 4 of the 9 tables have no migration file, so the schema is not reconstructible from git either.
Scored with securitymaxx — 10 checks, evidence required. PASS counts 1, PARTIAL 0.5, everything else 0. An item that could not be verified is UNKNOWN and scores zero, so the number is a floor rather than an estimate.
Read-only audit: source and config were read, and live probes were ordinary HTTP requests. Nothing was exploited and nothing was written to. Secret values are redacted to file and line — these reports get forwarded.
